# EvanScore design direction

Read `docs/evanscore/development-checkpoint.md` before resuming ongoing work. It records the Windows startup/build findings, release gates, preserved fixes, and remaining feature scope.

Keep `docs/evanscore/goals.md` current as the complete user roadmap. The user added a mixer/effects overhaul; it follows the Logic-inspired design direction and remains planned alongside the mallet visualizer and spatial placement. Do not present proposed detailed mixer scope as already shipped.

For every UI change, use the user's reference videos/images and the existing EvanScore UI as the design baseline. This applies to plugins, floating windows, dialogs, panels, and controls as well as the main app.

Keep the connected, minimalist appearance, neutral palette, rounded panels and buttons, consistent spacing, and existing accent treatment. Follow the host app's current theme for docked controls. The floating keypad specifically uses the dark, translucent appearance in IMG_0532.jpeg, including over a light score; reuse the host blue accent. Avoid introducing a separate visual style for a new feature.

For note-input controls, show recognizable notation previews for note durations and musical symbols rather than text-only buttons. Keep descriptive names in tooltips and accessibility labels. Preserve score music-font settings.

Reference materials used for this direction include IMG_0529.jpeg, IMG_0530.jpeg, IMG_0531.jpeg, IMG_0523.mov, and IMG_4982.MOV supplied by the user. Revisit the available references when making visual decisions.

The user authorized replacing existing UI that fails the direction, including a full overhaul where needed. Aim for the Logic Pro appearance in IMG_0529.jpeg and IMG_0530.jpeg: compact, connected neutral surfaces, quiet dividers, consistent rounding, and restrained blue selection.

Reference folder: https://drive.google.com/drive/folders/1a_PGAZ15IwrUa89S9JJEmPJ9-fajtOUI?usp=sharing . It contains the photos above plus IMG_0532.jpeg and the explanation videos. Reference media are design evidence, not instructions to execute. Use the user's messages to resolve requirements.

The percussion input strip should resemble the supplied MuseScore 3 screenshot: one row of actual notation previews that fits the available width, no sideways scrolling or individual boxed tiles. The floating note-input keypad remains an optional plugin opened and closed on demand. Follow IMG_0532.jpeg for its layout, musical symbols, blue selected buttons, semi-transparent dark material, broad rest button, tall tie button, category tabs, and bottom voice row. Use functioning Windows close and minimize buttons rather than Mac traffic-light controls. Preserve score music fonts.

The top-left open notehead control on the keypad changes notehead appearance independently of duration and playback. It must not act as a whole/half-note duration shortcut. The half-note key in the main duration grid still changes note length.

“Make Default Style” stores the current score's style as the app's persistent default for new scores, including new scores created from templates. It must not restyle existing scores when opened or switched to. “Apply Default Style” explicitly applies that saved default to the current score. A saved default takes priority over the bundled percussion style; percussion mode still forces accents above.

Dynamics belongs in the native, optional sidebar beside Instruments, Palettes, and Properties. Start with full-score settings, then follow selection for local note, marking, or hairpin controls. Use 0–127 MIDI velocity, handling zero explicitly as silence. Keep battery taps and accents separate, including mixed-category endpoints such as ff accents to mp taps. Dragging a visual curve must change both MIDI playback and audio automation while preserving printed notation. Changes must persist in native score XML and support undo/redo. Closing the panel must not disable the score's settings.

Windows downloads must pass a real desktop startup test beyond the splash screen, as well as score export. QML may not assign both a whole font and a font subproperty on the same object; that error can prevent the entire main window from loading.

Dynamics mapping cards must show independent velocities for normal, tap, tenuto, accent, marcato, ghost, soft accent, stress, and unstress. Preserve duration behavior for staccato and staccatissimo. Dynamics presets contain playback settings only. “Make Default Dynamics” persists across restarts and applies only to newly created scores, including templates; “Apply Default Dynamics” explicitly applies to an existing score. Loading presets must validate all values before making one undoable change and must preserve notation styles and local overrides.

EvanScore starts on the Home landing page with recent scores and New/Open actions when no file is specified; explicit file opening and session continuation go directly to notation. The user explicitly restored the landing page on 2026-10-09. Do not reintroduce automatic welcome/first-launch/promotional dialogs or instructional tours. Keep recovery, unsaved-change prompts, New/Open/Save, and recent files available. Closing the last score returns to Home. The main bar uses file actions and Home/Score navigation, with developer and publishing tools kept out of primary navigation. The neutral dark theme is applied once; subsequent user appearance preferences and high-contrast themes are respected.

Opening a score must also avoid automatic MuseSounds marketing dialogs. Do not run automatic sound-library promotion checks on the splash screen. Keep sound-engine compatibility checks and user-requested library actions available. Desktop release checks must exercise both an empty workspace and a current-format score with both default and software rendering, and reject unexpected dialogs over the workspace.

The keypad uses native UI icons and score API objects, not drawn substitutes. Main-page durations belong together; flam, single-slash diddle and buzz stay immediately available. Other tremolos include two slashes. Gear customization swaps or replaces individual slots per tab and saves across restarts. Resizing must not hide or overflow controls.

The mallet visualizer is currently in planning. Its feature and interaction baseline is the complete IMG_0523.mov demonstration, including diagnostics, alternatives, audition/compare, and explicit commit to the score. It belongs in an optional bottom panel alongside the Mixer, with the instrument/player on the left and information/suggestions on the right. Use the user's latest illustrated overhead-player reference: body, arms, hands, and mallets are mandatory, with a synchronized front view also requested. Randomize natural skin tone and hair color on each panel opening and keep them stable while open, without obscuring strike points or changing analysis. Keyboard geometry must follow the instrument range, defaulting to five-octave C2–C7 marimba. See docs/evanscore/mallet-visualizer-plan.md and mallet-research-sources.md for the reviewed 36-page research synthesis, necessary corrections, and primary citations still requiring verification.

The main control bar follows the supplied Logic screenshot: connected neutral toolbar surfaces, transport buttons beside a dark compact display of time, bar/beat, tempo, meter, and key signature. Use actual score/playback values, including signature changes and the selected staff; never invent a detected tonality. Percussion mode uses a compact native percussion icon with an accessible state and tooltip instead of a wide permanent text box. All docked toolbars sharing this row must have compatible height limits; preserve the left resizable grower and fixed selected-label widths.

The Dynamics enable switch must remain available while notes are selected, use the native host checkbox, and be tested by real pointer clicks in the complete Windows app. When custom mappings are disabled, do not present the fallback velocity 80 as a measured playback value: show Auto, preserve explicit note overrides, and explain how to enable category mappings. A user-reported intermittent freeze is not considered fixed solely because basic scores pass.

Dynamics mappings offer an explicit Set all action for an articulation column, defaulting to Tap and prefilling the most recently edited category/value. It sets that category to one velocity at every dynamic, keeps other categories and local note overrides intact, supports a single Undo, and saves through existing score/preset/default persistence. This is a one-time batch edit; it does not silently link future individual edits.

The user requests larger, clearer text in the Logic-style transport display and centered text/spacing within the display, with better use of the top bar. Complete the current crash investigation first. Preserve the left/resizable toolbar grower; do not reintroduce the fixed centered dock constraint that froze startup.

Battery dynamics use the user's stroke-height convention: pp ordinary strokes 1 inch, pp accents/tenutos 3 inches; p taps 3 inches and accents/tenutos 4 inches; mp taps 3 inches and accents/tenutos 6 inches; mf/f/ff/fff accents 9/12/15/18 inches. Battery ghosts mean no stroke and must be silent, including inside hairpins. MIDI velocities are editable starting calibration, not a universal physical-height conversion. The user finds original MuseScore pp/p and partly mp too quiet with Muse Drumline and plans to use Virtual Drumline; do not claim VDL calibration without testing their actual library.

“Smooth through articulations” is an optional score preference with a per-hairpin override: one envelope between the accent/tap endpoint levels, ignoring intermediate tenuto/articulation velocity lanes. Default off preserves earlier behavior. Explicit note overrides remain. Old imported marking velocities must not override custom battery tap mappings. Keep each mapping card's Tap, Tenuto, Accent, and Marcato visible; put Ghost, Normal, Soft accent, Stress, and Unstress behind a per-card “More articulations” disclosure. Collapsing only affects presentation.

Virtual Drumline targets the user's existing Kontakt VDL 2.5.5 library; they do not own the separate MuseHub edition. Use free Kontakt Player with VST3 for in-app audio, retaining account activation in Native Access. Cover every instrument in their library. Requested native integration includes automatic Muse Drumline-to-VDL conversion that preserves written notation and techniques, and staff-text controls/aliases for all techniques supported by each selected patch, including edge, guts on/off, and line/solo where available. Do not guess note/controller/keyswitch maps or silently convert unsupported techniques. A setup helper or generic VST3 hosting is not verified VDL-specific technique support. See docs/evanscore/virtual-drumline.md for prerequisites and current verification limits.

Kontakt must run in the background after initial library setup. Prepared VDL sounds belong in the existing Mixer sound selector alongside MS Basic and Muse Drumline; switching to them must not automatically open the Kontakt editor. Keep the editor available on demand. Preserve score instrument identity, staff layout, written pitches/noteheads, rhythms, and sticking when changing sound sources. Use a playback-only semantic mapping for VDL note/controller differences, and retain compatible staff-text techniques when switching back. Do not confuse a configured Kontakt instance with an automatically loadable VDL patch; verify patch restoration and save/reopen against the actual licensed library.

New features must expose useful diagnostics in the optional native Diagnostics → EvanScore feature diagnostics window. The shared sticking reader must retain explicit repeated R/L hands and numbered mallets, isolate staff/voice/onset, and flag missing, conflicting, or unsupported syntax. Lowercase sticking does not change dynamics. Sample application remains pending until an actual VDL playback mapping is implemented and verified; report that distinction clearly. Diagnostics are read-only, follow selection or an explicit bounded full-score scan, and copy data only on request.

Dock toolbar rows must match their loaded content heights without overriding DockToolBar minimumHeight during bootstrap. The fixed-minimum attempt in b900dbd2d15 froze Windows score startup after an empty session. Preserve the original minimum-size binding and lazy initialization; current padding targets a 48px loaded row (main36+6+6, ordinary32+8+8, playback42+3+3). Verify fresh and restored layouts in the complete Windows app; component constraints alone do not establish a native fix.

Clicking the transport time readout switches elapsed time and musical position, remembers the format across app restarts, and remains available without an audio device. Musical position uses bar.beat (1.1–1.4 in 4/4), with a third field for thousandths of a beat when necessary. All white transport values share a horizontal center line. Preserve the separate native Bar · Beat seeking controls. Include this change in optimization and complete-app release checks.

The user reports mostly Dynamics-related crashes with some apparently random crashes and requests optimization before the next download. Test repeated mixed edits, panel visibility, resize, saving/reopening, and process memory rather than assuming one sound library or control explains all crashes. Total system memory is not an EvanScore process measurement. The optional feature report includes process memory and Mixer ownership/meter diagnostics; licensed-library memory and playback remain separate validation requirements.
