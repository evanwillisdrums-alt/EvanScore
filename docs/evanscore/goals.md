## Full roadmap

1. **Reliable Windows app and downloads.** Responsive startup beyond the splash, clean score opening/closing, tested save/export, meaningful regression/crash checks, memory measurements, and a complete extracted ZIP. Do not claim a live sound-library crash is fixed without evidence.
2. **Full reference-driven UI overhaul.** Match IMG_0529 closely in button order/placement and proportions across the whole app, including Home, dialogs, preferences, panels and plugins; use practical creative liberties. Compact icon navigation/tools, transport beside them, captions below the dark readout, thin notation row, connected medium gray surfaces and blue selected pills. Larger readable transport text with white values aligned horizontally; clicking time switches elapsed time/bar.beat and remembers the choice. Centered time/bar/beat/tempo/meter/key display, neutral surfaces, rounded controls, restrained blue selections, and consistent spacing. Restore Home/recent files; keep automatic beginner tours and marketing popups out of the way. Preserve score music fonts.
3. **Persistent percussion mode.** Remember mode across restarts, apply the supplied percussion style, default unpitched accents above with manual placement/direction overrides, and use a compact mode control. Regular text uses Arial; larger/title text uses Arial Black as specified by the score style.
4. **Permanent style defaults.** Make Default Style stores the current style for new scores/templates across restarts. Existing scores keep their style until Apply Default Style is explicitly used. User defaults take priority over the bundled percussion style. Include a separate score-wide stem-length control that also affects notes skipped by conditional Shorten stems.
5. **Native visual dynamics.** Optional sidebar beside Palettes/Properties; score-wide controls by default and selection-specific note/marking/hairpin controls. Precise 0–127 values including silence, separate Tap/Tenuto/Accent/Marcato and extra articulation mappings, per-category Set all, presets/files, permanent defaults, undo, and native score persistence. Keep the main four categories visible; collapse extras individually per dynamic.
6. **Draggable crescendo/decrescendo curves.** Linear/exponential/logistic-style shaping and delayed/early growth, exact articulation-aware endpoints, optional Smooth through articulations to bridge accent→tenuto→tap passages, explicit local overrides, and shared behavior in audio/MIDI playback. Printed hairpins remain notation.
7. **Useful battery defaults.** Follow the user's pp/p/mp/mf/f/ff/fff stroke-height conventions, generally constant three-inch taps with the pp exception, equal accent/tenuto levels at quiet dynamics, and silent battery ghosts. Raise the quiet end relative to original Muse Drumline behavior, while keeping velocities editable and auditioning against the actual VDL patches.
8. **Virtual Drumline inside EvanScore.** Host the user's existing library through free Kontakt Player with VST3, running in the background after initial setup. Prepared VDL sounds use the same Mixer sound selector as MS Basic and Muse Drumline; the Kontakt editor opens only on request. Changing sounds preserves the same score instruments, staff layout, written pitches/noteheads, rhythms, and sticking, using playback-only mappings for library differences. Provide a tested setup route, discover the player, preserve patch configuration across saves/restarts, and cover battery, keyboard, concert, auxiliary, and all other instruments in their library. The separate MuseHub edition is not required for this route.
9. **Automatic Muse Drumline-to-VDL conversion.** One operation maps techniques to the matching VDL patch while preserving the written score, rhythms, dynamics, articulations, and sticking. Avoid manual per-note remapping. Keep conversion undoable and flag unsupported/ambiguous equivalents.
10. **VDL staff-text technique control.** Native offline dictionary with user-friendly aliases such as edge, halfway, center, guts on/off, and line/solo where the selected patch supports them. Expose other documented VDL techniques and translate them to the correct notes/controllers/keyswitches. Support resets, playback from the middle, and repeats; do not offer techniques a patch cannot play.
11. **Customizable floating keypad and input strip.** Optional translucent keypad with native symbols/icons, logical duration/articulation grouping, flams/diddles/buzzes, all tremolo counts, correct tie/beam previews, working Undo/Redo, Windows close/minimize, corner resizing, and saved per-tab button customization. The top-left open notehead changes appearance independently of duration/playback. The percussion input strip resembles the legacy compact notation row and fits without sideways scrolling.
12. **Complete keyboard/mouse bindings and notehead control.** Bind notation actions such as flam, diddle, and roll to keyboard and side/middle mouse buttons; show conflicts clearly. Make notehead edits easy while preserving playback where requested. Preserve existing native shortcuts and editing workflows.
13. **Optional mallet visualizer bottom panel.** Mixer-like dock, matching the full reference video: range-correct bars and accidental overhangs; five-octave C2–C7 default marimba; mandatory overhead body/arms/hands/mallets; Front view removed for now per the latest request; Stevens grip with fingers/separate shaft holding positions; readable compact rendering and detailed reference-matched diagnostics and alternative explanations; skin/hair variation on opening that stays stable while open. Read sticking, show chords/hand positions, diagnose playability using literature-informed rules, suggest alternative positions/voicings, audition/compare, and explicitly commit score edits with Undo. Panel opens/closes on demand.
14. **Visual spatial placement.** Optional stage/panning panel with draggable instrument positions and editable auditory placement. Include spreading a line or ensemble where the sound engine supports independent voices/players; do not fake independent audio from a single inseparable patch.
15. **Mixer/effects overhaul — newly added.** Redesign the mixer and effects workflow in the same Logic-inspired UI. Proposed scope: clearer readable channel strips and meters; practical volume/pan/mute/solo access; organized instrument groups; visible effect chains with bypass/reorder; visual effect controls such as EQ curves where supported; presets/defaults; and clear save/undo behavior. Confirm detailed routing, buses, sends, and effect-processing scope against the host architecture before implementation. Keep advanced controls accessible without permanently crowding the score.
16. **Quality of life and optimization throughout.** Requested playback options, including smooth hairpins through articulations, default on in new scores; saved preferences and explicit overrides take precedence. Responsive selection-following panels, keyboard access/tooltips, remembered layouts, useful contextual diagnostics/highlights, safe defaults, and fewer unnecessary clicks. Measure startup, repeated edits, memory growth, and sound-loading behavior; optimize verified bottlenecks. Keep optional tools optional and report verification limits honestly.

17. **Shared sticking and feature debug window — newly added.** Read native sticking markings and preserve explicit repeated hands for hand-specific VDL samples, then reuse the same assignments for the mallet visualizer. Retain numbered mallets without inventing a numbering/grip convention. Add an optional Diagnostics window for added features, especially sticking: recognized source markings, staff/voice/onset, assignments, dynamics/overrides, sample mapping/application status, and actionable missing/ambiguous/unsupported reports. Refresh, selected/full-score scope, copy report, and bounded scanning keep it practical. Actual VDL sample application must be separately implemented and tested.
